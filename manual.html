1. これは何か

ビリヤードの試合を、台の脇で片手で記録するための道具です。ブラウザで動きます。

  • スコアの欄を押すだけで点が入ります
  • ハンデ・ブレイク方式・時計を試合ごとに決められます
  • 終わった試合は自動で貯まり、勝率やマスワリ率が出ます
  • 電波が無くても動きます（一度開けば、そのあとは通信不要）

アドレス: https://hiroshit164820-create.github.io/pool-score/

2. はじめに（スマホに入れる）

ブラウザのままでも使えますが、ホーム画面に入れておくと普通のアプリのように開けます。

iPhone（Safari）

  1. Safari で上のアドレスを開く
  2. 下の「共有」ボタン（□に↑）を押す
  3. 「ホーム画面に追加」を選ぶ

Android（Chrome）

  1. Chrome で上のアドレスを開く
  2. 右上の「︙」を押す
  3. 「ホーム画面に追加」を選ぶ
最初にやっておくこと：自分を登録する

「選手」の画面の上にある ★自分を登録 から、自分の名前を1つ登録します。 これを入れておくと、ホーム画面に自分の勝率が出て、成績が自分中心に読めるようになります。

3. 試合を記録する

① 種目を選ぶ

「種目」の画面で、上から順に決めていきます。カテゴリ（一般／JPA／ハウスゲーム）を 押すと中身が開きます。ダブルスは種目の右の ダブルス で切り替えます。

② プレーヤーを入れる

名前を打つか、下に並ぶ登録済みの人を押します。 A側は青 B側は赤 の枠線で、 どちらの欄かが色で分かります。JPAの種目では、その人のスキルレベルも一緒に入ります。

③ 勝利条件を決める

  • ハンデなし: 何ラック（何点）先取かを1つ選ぶ
  • ハンデあり: A側とB側で別々の数字を選ぶ。強いほうを大きくします
  • ボールハンデ: 「N番以上で1点」という形で、弱いほうの得点になる球を増やします
  • JPA: スキルレベルを選ぶと、公式の表から持ち点が自動で決まります
  • イニング: 交代の回数を数えるかどうか（下の囲み参照）
イニングを数える／数えない

一般種目では、イニング（後攻から先攻に手番が戻った回数）を数えるかを選べます。

  • 9／10／8ボール・ダブルス・ローテーション … 既定は「数えない」
  • 14-1（ストレートプール） … 既定は「数える」（実力の指標になるため）
  • JPA … 公式スコアシートの土台なので常に数えます（選択欄は出ません）

種目を選び直すと、その種目の既定に戻ります。 「数えない」にしても中では数えているので、記録が失われるわけではありません。 試合中の帯・試合結果・履歴・成績に出さなくなるだけです。

④ ブレイクと時計

ウィナーズ（勝った側が次も撞く）かオルタネート（交互）かを選び、 先にブレイクする人を決めます。時計は「使わない／ショットクロック／チェスクロック」の3択です。

⑤ 内容を確かめて始める

いちばん下の「この内容で始めます」に、決めた内容が並びます。 見て問題なければ この内容で試合を始める を押します。

試合中の画面

  • 大きなスコアの欄を押すと点が入ります（種目によっては球のボタンから入れます）
  • 上の帯にラック数、いま何イニング目か（数える設定のとき）、マスワリの合計が出ます
  • いま撞いている側は、その人のパネルに印が付きます

下の帯には4つのボタンが並びます。

ボタンすること
🛠 スコア修正入れた記録の取り消し、イニングの増減。取り消した記録も残ります（競技規程の要件）
スコアシートJPA公式と同じ形のスコアシートを開閉します。開いている間は記録のボタン列が隠れます
無効球点にならずに落ちた球を数えます。点は増えません
次のラック手でラックを進めます（点が満ちれば自動でも進みます）

交代ボタンを押さなくても、A→B→A と入力すればイニングは1つ増えます。

終わりかた

勝利条件に届くと、確認の画面が出ます。内容（イニング数・セーフティ・マスワリ）を見て 終了して保存 を押すと記録に残ります。まだ続けるなら「まだ続ける」を押します。

途中でやめた試合は「中断中の試合」としてホームと種目の画面の先頭に出ます。 あとから続きを記録できます。

6. 記録はどこにあるか

記録は、いま使っている端末のブラウザの中だけにあります。 サーバーには送っていません。

  • 別のスマホやパソコンで開いても、記録は共有されません
  • ブラウザの「サイトデータを消去」をすると記録も消えます
  • 残しておきたいときは、履歴や成績の「表計算へ」で CSV に書き出してください

保存の仕組みは localStorage です。試合の本体と、一覧用の索引を分けて持っています。

7. 相手に記録を送る

片方だけが記録して、終わったら相手に送れます。 両方の端末で記録を付ける必要はありません。

送る

  1. 「履歴」で送りたい試合を出す
  2. 相手に送る を押す
  3. LINE などの送り先を選ぶ（共有が使えない端末では、リンクが写されるので貼って送ります）

受け取る

  1. 届いたリンクを押す
  2. 「届いた試合」の画面が出るので、中身（種目・スコア・日時）を見る
  3. この試合を取り込む を押すと、履歴と成績に入ります
名前が違っていても大丈夫です

取り込む前に「この人は誰ですか」で、送られてきた名前を あなたの端末の選手に結び付けます。

  • 名前がそのまま一致する人がいれば、はじめから選ばれています
  • 一致しなければ何も選ばれず、「成績に入れない」になります。 そのまま取り込むと記録だけが残り、誰の勝率も動きません
  • 「登録済みから選ぶ」「新しく登録する」「成績に入れない」の3つから選べます
  • 一度結び付けたら覚えるので、次からは自動で選ばれます

知っておくこと

  • 記録はリンクそのものに入っています。サーバーには送られません （URLの「#」より後ろはサーバーに届かない決まりです）
  • 同じ試合をもう一度取り込もうとすると警告が出ます （ボタンが「それでも取り込む」に変わります）
  • 試合1つぶんのリンクは1,000〜2,000字ほどです。 LINEなら問題ありませんが、文字数の少ない送り方（SMSなど）では切れることがあります
  • とても長い試合は、1球ごとの記録を省いて結果だけを送ります （そのときは取り込み画面にその旨が出ます）
  • 取り込んだ記録はそのあと同期しません。 送ったあとに送り主が直しても、こちらには反映されません

8. システム編：中の仕組み

作りの考え方

このアプリの土台は「出来事を並べて記録し、後ろから計算し直す」形です。 点数そのものは保存せず、「Aがラックを取った」「9番が落ちた」といった出来事（イベント）を 順番に積み、そこから毎回スコアを計算します。

  • 取り消しても記録は消えず、「無効になった」印が付くだけ（競技規程の要件）
  • 後から数え方を直しても、過去の出来事から計算し直せる
  • 種目ごとの違いはデータで表し、計算する部分は共通

ファイル構成

場所役目
index.html画面の骨組み。全画面が1枚に入っていて、表示を切り替える
data/種目・基礎ルール・点の付け方・ハンデ表・球の色。ここは全部データ
js/engine.jsスコア計算の中心。種目名による分岐を一切書かない
js/store.js保存と読み出し、成績の集計
js/ui_*.js画面ごとの処理（設定・試合・履歴・選手・成績・配置・ハウスゲーム）
js/share.js / js/ui_import.js記録をリンクにして渡す／届いた記録を取り込む
js/shotclock.js / chessclock.js2種類の時計
style.css / css/v2.css見た目。v2.css が後から上書きする
sw.jsオフライン用。ファイルを変えたら CACHE_VERSION を上げる
_test/検証。実ブラウザ40本＋計算だけの4本

おおよその規模：本体（js＋data）約12,100行、見た目（css）約5,900行、検証48本。

種目を3つの軸に分けている

12種目を switch(gameId) で分けると、種目が増えるたびに分岐が増えます。 そうならないよう、種目を次の3つの組み合わせとして表しています。

軸置き場例
基礎種目（base）data/rules_data.jsnineball／tenball／eightball／rotation／straight／bowlard／kailun
点の付け方（scoring）data/scoring_data.jsrack（ラック単位）／straight（球1個＝1点）／bowlard／step
勝利条件（goal）data/games_data.jsfree（自由）／jpaSL（JPA表）／jpaSL8／manual

9. システム編：種目を増やす

種目を増やしても、スコア計算（js/engine.js）は触りません。 engine には種目名が1つも書かれていない決まりで、 _test/engine.test.js の「設計ゲート」が自動で見張っています。 種目名を直書きすると検証が落ちます。

触る場所は2つ

  1. data/games_data.js に定義を1つ足す
  2. js/ui_setup.js の GAME_GROUPS に1行足す （種目一覧と、成績の種目別の並び順の唯一の出どころ）
// data/games_data.js
"7ball": {
  label: "7ボール",
  base: "nineball",     // 基礎種目（rules_data.js）
  scoring: "rack",      // 点の付け方（scoring_data.js）
  goal: "free",
  playersPerSide: 1,
  mode: "rack",
  goalType: "racks",
  inningsOption: true,  // イニングを数えるかを設定で選べる
  goalPresets: [{ label: "3先", v: 3 }, { label: "5先", v: 5 }],
},

// js/ui_setup.js の GAME_GROUPS（「一般」の items）
{ id: "7ball", doubles: null },
この2か所だけで動くことは実際に確かめてあります。 上の「7ボール」を定義に足しただけで、engine を1行も触らずに ラックの加算と勝敗判定が正しく動きました（2026-08-21 に実測）。

必要なときだけ足す場所

  • これまでに無い基礎種目（球の並べ方・反則の扱いが違う）→ data/rules_data.js
  • これまでに無い点の付け方→ data/scoring_data.js
  • 新しいハンデ表→ data/handicap_data.js
気をつける点（正直に書いておきます）
  • 成績の種目別カードの中身は js/ui_players.js が 種目IDで分岐しています（ボウラード／ローテーション／14-1／9ボール系）。 新しい種目は共通の行だけになります。壊れませんが、専用の行は出ません
  • カイルンと5-9/5-10は engine と別系統です （js/money_game.js／js/ui_kailun.js）。 A/Bの2サイドを前提にしない進行（3人以上など）はこちら側の作りになります
  • js/store.js に1か所だけ jpa_8ball の直書きがあります （JPAポイントの満点を 3 と 20 で分けるところ）
  • ファイルを新しく増やしたら sw.js の一覧と CACHE_VERSION も更新します

10. システム編：検証と公開

検証

変更したら、必ず検証を通してから公開します。

cd D:\Claudecode\pool-score

_test\run_all.bat          … 全部（44本・50分ほど）
python _test\xxx_test.py   … 1本だけ
python _test\live_test.py  … 公開されている実物を実ブラウザで確認（19項目）
結果をパイプに通して読まないこと。 テスト | tail のように書くと、受け取る終了コードが tail のものになり、 落ちた検証を「成功」と読み違えます。1本ずつ実行して終了コードを直接見ます。

公開

  1. アプリのファイルを変えたら sw.js の CACHE_VERSION を上げる （上げないと、スマホに古い画面が残ります）
  2. main に push すると、GitHub Pages が1〜2分で自動で作り直します
  3. 「ビルドが成功した」と「配信されている中身が新しい」は別です。 次のコマンドで実物を見ます
curl -s -A "Mozilla/5.0" "https://hiroshit164820-create.github.io/pool-score/sw.js?cb=%RANDOM%" | findstr CACHE_VERSION

11. 困ったとき

こうなったこうする
直したはずの画面が古いままスマホの場合はアプリを一度閉じて開き直す。それでも古ければ、ブラウザで開いてページを再読み込みする
