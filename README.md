# ビリヤードスコア記録

試合中に片手でスコアを記録し、勝率などのスタッツを残していくアプリ。

## 使い方

**スマホ（本番）**

https://hiroshit164820-create.github.io/pool-score/

上のURLを開いてください。ホーム画面に追加すると、アプリのように全画面で使えます。

- iPhone: Safariで開く → 共有ボタン → 「ホーム画面に追加」
- Android: Chromeで開く → メニュー → 「ホーム画面に追加」

一度開けば**電波がなくても動きます**（ビリヤード場は電波が弱いことがあるため）。
記録は端末の中に保存されるので、他人には見えません。

**PC**

`起動する.bat` をダブルクリックするとブラウザで開きます。

※ 記録は端末ごとに保存されます。スマホとPCでデータは共有されません（移したいときは「書き出し」→「読み込み」）。

## デザイン

明るいクリーム地に、太い枠線とハードオフセット影（ぼかさない平らな影）を組み合わせたポップな配色です。
書体は **M PLUS Rounded 1c**（丸ゴシック）。読み込めない環境では BIZ UDGothic 等のUD書体に落ちます。

ボタンは押すと影が消えて沈みます。台の脇では画面をよく見ていないので、押せたかどうかが動きで分かるようにしています。

※ ダークモード連動ではなく、この明るい配色で固定です。

## 画面の使い方

試合中の画面は、大きなスコア欄が2つ並んでいるだけです。
**ラックを取った側のスコアをタップすると1加算されます。** 押すと一瞬だけ拡大して反応が返るので、押せたかどうかが分かります。

間違えたら下の「⟲ 取り消し」で1つずつ戻せます。特定の記録だけ消したいときは「⋯ 訂正」から選びます。

マスワリ・ブレイクエース・セーフティを記録したいときは、**先にそのボタンを押してからスコアをタップ**してください。

## 種目ごとの違いは自動で反映されます

- **10ボールにブレイクエースのボタンは出ません** — 10番は必ずフットスポットに戻すルールのため、概念自体が存在しないからです（NBA規程 第10章第4条第5項）
- **10ボールにセーフティのボタンは出ません** — 2026年6月のルール改定でセーフティコールが廃止されたためです
- ボタンが出ないこと自体が「その記録は取れない」という意味になります
- **14-1だけは操作が違います** — 球を1個入れるごとにタップします（1個=1点）。マスワリ等のボタンは出ず、代わりにファウルボタンが出ます

### 14-1の減点について

14-1は他の種目と違い、ファウルで点が減ります（NBA競技規定 第13章第9条）。

| 状況 | 減点 |
|---|---|
| ファウル1回 | −1点 |
| 3回連続でファウル | そのショットで**−16点**（ファウルの−1点＋スリーファールの−15点）<br>※1・2回目の−1と合わせると通算−18点 |
| オープニングブレイクが正常でない | −2点 |

そのため**スコアがマイナスになることがあります**。表示もマイナスのまま出ます。

## 検証

```
_test\run_all.bat
```

3つの検証をまとめて実行します（合計198項目）。

| 検証 | 内容 |
|---|---|
| `engine.test.js` | スコア計算。JPA1ラック=10点、ローテのラック跨ぎ得点、スリーファール、訂正の整合性など |
| `shotclock.test.js` | 時間計測。仮想時計を使うので実時間を待ちません。バックグラウンド化しても狂わないことも確認 |
| `browser_test.py` | 実ブラウザ（Chromium・iPhone相当の画面）で試合作成から履歴まで通しで操作 |

スクリーンショットは `_test/shots/` に出ます。

## ファイル構成

```
data/    ルールの定義データ（ここを直せば挙動が変わる。ロジックは書かない）
  rules_data.js      種目ごとの盤面ルール
  scoring_data.js    得点の計算方法
  games_data.js      12種目の定義
  handicap_data.js   JPAのSL表・チームポイント表など

js/
  engine.js      スコア計算の中核（純粋関数のみ。種目名の分岐を書かない）
  shotclock.js   ショットクロック
  store.js       保存
  ui_*.js        画面
  app.js         起動
```

**設計の要点**: 記録は「イベントの追記」として持ち、現在のスコアはそれを毎回畳んで計算します。
これにより、ローテーションのようにラックを跨いで得点が続く種目も、訂正の履歴を残す要件も、同じ仕組みで扱えます。

種目を追加するときは `data/games_data.js` に1行足すだけで、`js/engine.js` は触りません。
（この原則は `engine.test.js` の最後で自動チェックしています）

## 公開の仕組み

GitHub Pages で配信しています（リポジトリ: `hiroshit164820-create/pool-score`）。

`main` ブランチに push すると自動で反映されます。反映まで1〜2分かかります。

```bash
git add -A
git commit -m "変更内容"
git push
```

**ファイルを変更したときは `sw.js` の `CACHE_VERSION` を上げてください。**
上げないと、スマホに古い画面がキャッシュされたまま残ることがあります。

公開URLが実際に動いているかの確認:

```
python _test\live_test.py
```
